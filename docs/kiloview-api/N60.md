## 1. Authentication

`POST /api/systemctrl/users/login`

```http
App: {"language":"en"}
Content-Type: application/json
```

```json
{
  "username": "admin",
  "password": "YOUR_DEVICE_PASSWORD"
}
```

Read `data.token` and `data.alias`. Subsequent project requests send the token directly as the `Authorization` header value, with **no `Bearer ` prefix**, plus identity cookies and the same `App` header:

```http
Authorization: TOKEN_FROM_LOGIN
App: {"language":"en"}
Cookie: language=en; user=admin; alias=Admin; token=TOKEN_FROM_LOGIN
```

Use the actual returned alias, falling back to `Admin` only when absent. Token lifetime is not established here.

### PowerShell login and read-only checks

Load `Invoke-KvJson` from [Shared conventions](COMMON.md#powershell-json-validation-helper) first. Replace the illustrative address.

```powershell
$deviceBase = 'http://192.0.2.61'
$deviceCredential = Get-Credential -UserName 'admin'
$deviceUri = [uri]$deviceBase
$session = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$headers = @{ App = '{"language":"en"}' }
$login = Invoke-KvJson -Uri "$deviceBase/api/systemctrl/users/login" -Method POST -Headers $headers -Body @{
    username = $deviceCredential.UserName
    password = $deviceCredential.GetNetworkCredential().Password
}
if ([string]::IsNullOrWhiteSpace([string]$login.data.token)) { throw 'No API token returned' }
$headers.Authorization = [string]$login.data.token
$alias = [string]$login.data.alias
if ([string]::IsNullOrWhiteSpace($alias)) { $alias = 'Admin' }
$cookies = @{
    language = 'en'
    user = $deviceCredential.UserName
    alias = $alias
    token = [string]$login.data.token
}
foreach ($name in $cookies.Keys) {
    $cookie = New-Object System.Net.Cookie($name, $cookies[$name], '/')
    $session.Cookies.Add($deviceUri, $cookie)
}
$system = Invoke-KvJson -Uri "$deviceBase/api/systemctrl/system/getSystemInfo?version=true" -Session $session -Headers $headers
$hostname = Invoke-KvJson -Uri "$deviceBase/api/systemctrl/system/getHostname" -Session $session -Headers $headers
$modeResponse = Invoke-WebRequest -UseBasicParsing -ErrorAction Stop -TimeoutSec 8 -Uri "$deviceBase/api/codec/mode/get" -WebSession $session -Headers $headers
$mode = ([string]$modeResponse.Content).Trim().Trim('"')
if ($mode -notin @('encode', 'decode')) { throw "Unexpected N60 mode response: $mode" }
$system.data.version
$hostname.data
$mode
```

**Vendor difference:** v2.01 describes cookie-based login followed by `GET /api/systemctrl/users/session`. The current adapter does not make that session call and additionally sends raw-token Authorization. Treat these as different integration flows. [N60 API, §§1.1.1-1.1.2](https://enstatic.kiloview.com/wp-content/uploads/2025/09/N60-WEB-API-EN-Version2.01.pdf#page=6)

### Initial credentials

The adapter first attempts `POST /api/systemctrl/users/modify`. Its body for an existing admin account is:

```json
{
  "username": "admin",
  "id": "admin",
  "alias": "Admin",
  "password": "YOUR_NEW_DEVICE_PASSWORD",
  "confirmNewPassword": "YOUR_NEW_DEVICE_PASSWORD",
  "enable_web": true,
  "enable_api": true
}
```

On rejection it probes `POST /api/systemctrl/users/changePassword`, then `POST /api/systemctrl/users/initPassword` with the same body. Those fallback names are **Compatibility probes**, not proven portable alternatives. Reauthenticate with the replacement credentials afterward. The adapter changes these settings only when supplied credentials differ; it does not independently repair API permissions for an unchanged account.

Account renaming is not qualified here. License acceptance is also probed heuristically rather than backed by a stable universal endpoint; see section 12.

## 2. Inventory and status

| Method / path | Response fields used |
| --- | --- |
| `GET /api/systemctrl/system/getSystemInfo?version=true` | `data.version.serialNumber`, `data.version.softwareVersion` |
| `GET /api/systemctrl/system/getHostname` | `data.hostname` |
| `GET /api/networkmanager/network/GetLinkinfo` | `data[]`: `device`, `status`, `address`, `mac`, `method` |
| `GET /api/codec/mode/get` | Bare `encode` / `decode`, or a JSON string containing it |
| `POST /api/codec/encoder/main/get_capture` | Body `{}`; root or `data`: `signal`, `resolution`, or `width`, `height`, `framerate` |
| `GET /api/codec/decode/get` | Current source, output and receive-transport fields; generally in `data` |

The network adapter selects the first interface reporting `status: "up"`, falling back to the first row. A new controller should explicitly choose the intended interface when several links are active. `method: "static"` is treated as a static assignment.

The HDMI input probe treats empty, `0`, `none`, `no signal`, `unknown`, `offline` and `false` as absent, normalizing case, underscores and hyphens. On firmware 2.45, capture data can be at the JSON root. Do not require a `data` wrapper for that endpoint.

Useful decoder fields consumed by the project:

| Field | Meaning in the integration |
| --- | --- |
| `name`, `url`, `original_url`, `ip` | Selected source identity/address |
| `channel_name` and alternative channel/name fields | Displayed tuned channel |
| `ndi_connection` | Receiver transport readback |
| `output_resolution` | Reported output format |
| `output_mode`, `output_resolution_choose`, `output_framerate` | Whether identity-card output is already Auto |
| `hdmi_channels`, `line_out_channels`, `hdcp`, `out_colorspace` | Values preserved when changing output to Auto |

Read `softwareVersion` as the version string and retain the hardware serial separately from hostname/IP. The general shared envelope rules do not apply to the plain-text mode endpoint.

## 3. Network and hostname

### Static IPv4

Read `GetLinkinfo` first. Preserve the selected interface name and MAC from its returned record.

`POST /api/networkmanager/network/SetEthernets`

```json
{
  "ifname": "eth0",
  "address": "192.0.2.61",
  "netmask": "255.255.255.0",
  "gw": "192.0.2.1",
  "mac": "MAC_FROM_GETLINKINFO",
  "method": "static",
  "dns": "192.0.2.1"
}
```

All values above are strings. The request can drop the HTTP connection when the address changes. Reconnect at the new address, reauthenticate and compare the serial and network values. Do not mark the change successful merely because a timeout was expected. DHCP writes are outside the implemented workflow documented here.

### Hostname

`GET /api/systemctrl/system/setHostname?name=STUDIO-KV-002`

This **changes configuration despite using GET**. URL-encode `name`. Read back `/api/systemctrl/system/getHostname`. Prevent generic crawlers or prefetchers from following mutation URLs.

## 4. Encode/decode role

`POST /api/codec/mode/set?mode=decode`

The project sends no request body. Use `encode` for the opposite role, not N6's `encoder`/`decoder` strings.

This restarts codec services. The immediate HTTP result only confirms the mode request; wait for authenticated mode and target-service reads before subsequent writes. Read `/api/codec/mode/get`, then the encoder capture or decoder status endpoint. N60 transitions can take about a minute; the project uses longer recovery windows in its onboarding workflow.

Encoder/decoder mode is separate from the encoder's HB/HX selection described next. A decoder must not be treated as ready simply because the system/hostname endpoints answer.

## 5. Encoder profiles, identity and restart

### Select dedicated HB mode

| Method / path | Project body / verification |
| --- | --- |
| `GET /api/codec/encoders/get_encode` | Root or `data`: `encode_mode` |
| `POST /api/codec/encoders/choose_encode` | `{"encode_mode":"hb"}` |
| `GET /api/codec/streams/main_full/ndi-full/get` | Confirm HB `enable` is true |
| `GET /api/codec/streams/main/ndi-hx/get` | Confirm HX `enable` is false |

The project deliberately uses dedicated HB mode during onboarding and multicast configuration. This choice changes the encoder's stream behavior. It is not a requirement for every N60 application.

**Vendor difference:** the older `choose_encode` example uses `main` and `main_full` flags. Do not combine that older body with the current project's `encode_mode` selector. [N60 API, §2.5.2](https://enstatic.kiloview.com/wp-content/uploads/2025/09/N60-WEB-API-EN-Version2.01.pdf#page=36)

### Set NDI identity

`POST /api/codec/streams/main_full/ndi-full/set`

```json
{
  "group": "STUDIO",
  "group_server": "STUDIO",
  "channel_name": "CAM-02"
}
```

Read `/api/codec/streams/main_full/ndi-full/get`; the project checks retained `group`. Check the channel as well in a standalone integration. Set system hostname separately. Writing identity into an inactive HX stream can wake a combined mode and create duplicate advertisements, so the project's HB workflow only edits `main_full/ndi-full`.

### Restart the sender

`GET /api/codec/streams/main_full/reset`

This GET is disruptive. The project calls it after HB identity or sender-transport changes, then reads HB configuration until enabled. The listener URL/port can change, so refresh discovery before setting decoder presets. A larger port is used by this code as a tie-breaker for otherwise equally matched stale advertisements; it is not a general freshness guarantee.

### Handling “Request too often”

The adapter detects that message in application errors for selected requests and uses bounded delays. Do not assume rate limiting will always use HTTP 429. Stagger requests per device and read back before resending uncertain mutations.

## 6. Discovery Server and manual targets

### Discovery Server

`POST /api/codec/discovery/setDiscoveryServer`

```json
{
  "enable": true,
  "servers": [
    {"ip": "192.0.2.10", "group_name": "STUDIO"}
  ]
}
```

Read `GET /api/codec/discovery/getDiscoveryServer`. The project expects enabled state and a matching entry in `servers[]`, at the root or inside `data`. Reapply and read back after the final role is active: project findings indicate separate encoder/decoder codec settings.

**Vendor difference:** v2.01 describes `enable` plus singular `address`; current source uses `servers[]` with per-server groups. Verify the schema on other firmware. [N60 API, §2.2](https://enstatic.kiloview.com/wp-content/uploads/2025/09/N60-WEB-API-EN-Version2.01.pdf#page=27)

### Manual discovery

`POST /api/codec/discovery/addManualIpsGroups`

```json
{
  "groups": ["STUDIO"],
  "manuals": ["192.0.2.60", "192.0.2.62"]
}
```

These arrays contain NDI group names and sender IP addresses. The method changes discovery configuration. Do not infer whether every firmware appends or replaces previous targets solely from its name; the current adapter does not read that complete target list back.

`GET /api/codec/discovery/scan` returns source rows in `data[]`. Recursively process `children[]`; multiple channels from the same sender may be nested there. Fields used include `id`, `name`, `device_name`, `channel_name`, `group`/`group_name`, `ip`, `port`, `url`, `original_url`.

Use actual discovered URLs, preferring `original_url` where present. Do not construct an NDI listener URL using a presumed fixed port. A configured sender that is not running may have no discoverable source to save.

## 7. Decoder source selection and presets

### Select a discovered source

`POST /api/codec/decode/add`

```json
{
  "id": 1,
  "name": "STUDIO-KV-001 (CAM-01)",
  "url": "SOURCE_URL_FROM_DISCOVERY",
  "group": "STUDIO"
}
```

Use the numeric ID and other values from the selected discovery record; `1` above is illustrative. The identity-card routine falls back to `POST /api/codec/decode/addSpec` with the same object when necessary. Read `/api/codec/decode/get` and compare source name/URL. Selection alone does not prove a visible picture.

### Read and populate presets

`GET /api/codec/preset/get` returns a `data[]` preset bank. The project discovers usable numeric IDs from rows whose `id > 0` and `color` is empty. It excludes the colour/blank preset and determines capacity from the returned bank rather than hard-coding a count.

`POST /api/codec/preset/add`

```json
{
  "position": 1,
  "channel_name": "CAM-01",
  "device_name": "STUDIO-KV-001",
  "enable": 1,
  "group": "STUDIO",
  "ip": "192.0.2.60",
  "name": "STUDIO-KV-001 (CAM-01)",
  "port": 5961,
  "url": "SOURCE_URL_FROM_DISCOVERY",
  "original_url": "SOURCE_URL_FROM_DISCOVERY",
  "type": "ndi"
}
```

`position`, `enable` and `port` are numbers. Use a returned usable preset ID as `position`, and replace **all** illustrative source values, including `5961`, with discovery data. The project uses identical values for `url` and `original_url`.

Remove a feed with `POST /api/codec/preset/remove`, body such as `{"id":1}`. This clears that saved feed. Onboarding replaces the feed bank in deterministic hostname order and clears old unused feeds; preserve user presets if implementing a less destructive operation.

Read `/api/codec/preset/get` after edits. The project checks expected slot IDs and matching IP or channel; a stricter client can also compare URL and group. Saving a preset and activating it are separate operations. To select a saved preset, use `/api/codec/decode/add` with its returned numeric `id`, then verify current decoder status.

## 8. Multicast and unicast

### HB encoder

`POST /api/codec/streams/main_full/ndi-full/set`

```json
{
  "connection": "multicast",
  "netprefix": "239.194.2.0",
  "netmask": "255.255.255.0",
  "ttl": "1",
  "types": "ndi-full"
}
```

**Send TTL as a JSON string.** The adapter records that a JSON number can silently revert to the firmware default of 127. This is a project compatibility finding; avoid automatic conversion by serializers.

Verify `connection`, `netprefix`, `netmask` and numeric equivalence of `ttl` using `/api/codec/streams/main_full/ndi-full/get`, then restart `/api/codec/streams/main_full/reset`. The project first ensures dedicated HB mode before making this change.

Revert with the same `set` endpoint:

```json
{"connection": "unicast", "types": "ndi-full"}
```

Read back and restart the HB sender again. The sender uses `connection`; the decoder uses `ndi_connection` below.

### Decoder

`POST /api/codec/decode/setConnection`

```json
{"ndi_connection": "multicast"}
```

Read `/api/codec/decode/get` and verify `ndi_connection`. Register the relevant sender addresses and groups through `addManualIpsGroups`. Revert by sending `{"ndi_connection":"unicast"}` to the same endpoint, then read back.

### Historical allocation discrepancy

**Hardware:** On 13 August 2026, an N60 encoder retained the requested `239.193.1.0/24` through the API while packet capture found media on `239.255.x.x` destinations. An HB sender restart did not establish on-wire compliance in that test. The report does not identify the encoder firmware, so do not attach this observation to a guessed build or claim it was resolved by subsequent decoder tests. [Multicast report](SOURCES.md#historical-hardware-evidence)

API readback therefore proves saved configuration, not actual allocation enforcement. The separate 14 August report records N60 `2.45.0014.0170` decoders receiving an N6 multicast sender; that does not qualify N60 encoder allocation behavior.

## 9. HDMI output and blanking

### Follow the source format for identity cards

The identity-card workflow selects the source first, then inspects `/api/codec/decode/get`. If needed, it writes:

`POST /api/codec/decode/output_set`

```json
{
  "output_resolution": "auto",
  "output_framerate": 0,
  "hdmi_channels": 2,
  "line_out_channels": 2,
  "hdcp": 1,
  "out_colorspace": 0
}
```

The last four numbers are fallback examples. Preserve their actual current values when available. This changes HDMI output negotiation. The project uses Auto because a decoder can select the identity source while a forced output format leaves the attached display black. Source selection can restore a saved forced output, so normalize after selection.

For a standalone client, read back the resulting output settings and inspect the screen as needed. The current helper sends the output setting but does not perform a separate post-write output-settings verification.

### Blank the output

1. `POST /api/codec/decode/add` with numeric zero:

```json
{"id": 0}
```

2. `POST /api/codec/preset/set_blank_color`:

```json
{"BlankColor": "#000000"}
```

The capital `B` and `C` are significant. The project's former camel-cased serialization produced `blankColor` and HTTP 422. Use a dictionary/map or otherwise preserve the exact JSON key.

For **zero-preset selection only**, firmware 2.45 can return:

```json
{"result": "", "msg": ""}
```

The adapter accepts that response or `result: "ok"`, then confirms `name` and `url` are empty and `ip` is empty or `0.0.0.0` via `/api/codec/decode/get`. Do not use the strict shared helper unchanged for this one selection response, and do not treat all empty result strings as success.

**Hardware:** September completion checks passed for two N60 `2.45.0014.0170` decoders; those were application/device API checks, without independent visual inspection. [September report](https://github.com/JohnDevAc/Kiloview-Job-Configurator/blob/9d431ce25f83e37e0f05f3301ade5b2ac8ac9cd9/E2E-ONBOARDING-TEST-2026-09-05.md)

## 10. KiloLink

`GET /api/kilolink/networks`

The interface list is at root `list`, for example `{"result":"ok","list":["eth0"]}`. The project uses the returned names and falls back to `eth0` if that property is absent.

`POST /api/kilolink/set`

```json
{
  "ip": "192.0.2.10",
  "port": 50000,
  "ifname": ["eth0"],
  "key": "YOUR_KILOLINK_ONBOARDING_CODE",
  "crypto": false,
  "enable": true
}
```

`ifname` is an array of the device's chosen network interfaces. `port` is the numeric device-link service port, distinct from the KiloLink web port. The example follows the project's unencrypted device-link configuration. Confirm registration through the actual KiloLink/device status workflow; the N60 adapter's setup method checks request acceptance but does not itself read the full KiloLink configuration back.

**Vendor difference:** v2.01 prints capitalized `/api/KiloLink/...`; the current N60 adapter uses lowercase `/api/kilolink/...`. Preserve the implementation's casing for this firmware baseline. [N60 API, §4.1](https://enstatic.kiloview.com/wp-content/uploads/2025/09/N60-WEB-API-EN-Version2.01.pdf#page=63)

## 11. Firmware upload

`POST /api/systemctrl/system/upload`

Use multipart binary field `file`, plus text `path` containing the filename, with the N60 authentication headers/cookies. See [Shared multipart format](COMMON.md#4-firmware-upload-contract). The complete shared package formatter is implemented and has offline regression coverage. September's hardware run skipped flashing the N60s because they already had the selected version, so it is not an N60 firmware-upload acceptance test.

After an upload, reconnect and reauthenticate, then read `data.version.softwareVersion` from `getSystemInfo?version=true`. Verify the target version and intended serial before further configuration.

## 12. Troubleshooting and unsupported assumptions

| Symptom | Check |
| --- | --- |
| Login token returned, later calls fail | Raw Authorization value, identity cookies, App header and account permissions |
| Capture JSON appears to have no `data` | Inspect the root payload on 2.45 |
| Mode parsing fails | Endpoint can return a string rather than an object |
| Request rejected as too frequent | Use bounded backoff; inspect application-level error text |
| TTL becomes 127 | Ensure request TTL was a JSON string |
| Discovery works in only one role | Reapply and verify role-specific Discovery Server settings |
| Duplicate NDI advertisements | Confirm HB/HX mode; avoid writes to the inactive HX profile |
| Missing channel in discovery | Recursively examine `children` |
| Black screen with selected source | Inspect forced HDMI output and actual display compatibility |
| HTTP 422 setting blank colour | Verify exact `BlankColor` spelling |

License acceptance candidates include `/api/users/accept_eula.json`, `/api/systemctrl/system/acceptEula`, `/api/systemctrl/system/setEula`, `/api/systemctrl/eula/accept`, `/api/systemctrl/license/accept`, `/api/systemctrl/system/acceptAgreement` and `/api/systemctrl/system/setAgreement`, plus routes found in web assets. These are **Compatibility probes**, not confirmed contracts. The current helper does not independently verify a retained license-acceptance state.

For time/system administration, detailed encoder audio/video, PTZ and intercom options, consult the vendor manual's corresponding modules. They are outside this project's qualified integration scope. [Official N60 API PDF](https://enstatic.kiloview.com/wp-content/uploads/2025/09/N60-WEB-API-EN-Version2.01.pdf)
